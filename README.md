# 叠羊记 SheepStack

> 一个面向**抖音小游戏**的三消叠叠乐，对《羊了个羊》的升级复刻。
> 一句话卖点：**不坑人的羊了个羊。**

本仓库包含两部分：

1. **研究** —— 《羊了个羊》为什么会爆，以及它为什么又迅速退潮（`docs/01`）
2. **实现** —— 一个可运行的游戏核心 + 完整的广告变现层，
   带 36 个单测和一个浏览器 Demo

## 核心差异：牌面保证有解

《羊了个羊》第二关的难，很大程度上是**随机死局**的难 ——
玩家可能从第一步就已经必败，但要到卡槽爆掉才知道。
打了 50 次，第 51 次还是全靠运气，学不到任何东西。

本项目反过来做：**先造一条通关路径，再反推牌面。**

```
生成牌堆几何结构 → 取一条拓扑序（合法取牌顺序）
                 → 沿序分配花色，同时模拟卡槽不溢出
                 → 这条序本身就是通关路径
```

于是「无解」在数学上不存在，玩家每一次失败都确实是自己走错了。
难度改由**卡槽压力**来调，需要提前规划，而不是碰运气。

证明和实现见 [`src/core/solvable.ts`](src/core/solvable.ts)，
由单测守着（60 关 × 5 种子 = 300 副牌，每副都实际打通一遍）。

这条性质还带来两个额外好处：

- **洗牌道具重新保证有解** —— 玩家自己走进死路也有救，
  这和原作「纯随机洗牌，可能越洗越死」是本质区别
- **复活后重新保证有解** —— 看完 30 秒广告换来的必须是一个真能打通的局面

### 效果：技巧真的有用

`npm run balance` 用三档机器人跑通过率（每关每档 40 次）：

| 关卡 | 牌数 | random（乱点） | greedy（普通玩家） | planner（老手） |
|---|---|---|---|---|
| 12 | 27 | 60% | 98% | 100% |
| 25 | 45 | 3% | 85% | 95% |
| 35 ★ | 69 | 0% | 38% | 68% |
| 50 ★ | 90 | 0% | 5% | 33% |
| 55 | 69 | 0% | 20% | 80% |

★ = 尖峰关（故意做的话题关，对应原作的「第二关」，但**可以被打过去**）

**最重要的是 greedy 和 planner 的差距。** 第 55 关一个 20%、一个 80% ——
决定胜负的是打法而不是运气。这正是原作做不到的。

## 广告设计

三条原则，每一条都落成了代码里的配置项和断言：

1. **广告是玩家主动买的服务，不是我们强塞的税。**
   11 个广告位里 9 个是激励视频，插屏只有 1 个且有 240 秒冷却。
2. **永远不要因为广告没加载出来而惩罚玩家。**
   无填充照样发奖（标记 `fallback: true`，不计入广告收入）。
3. **前几分钟一分钱都不要赚。**
   冷启动 180 秒静默 + 前 5 关完全无广告。

### 失败后看广告继续

```
第 1 次复活 → 看广告 → 清 3 张
第 2 次复活 → 看广告 → 清 2 张      ← 递减，让广告是救援而不是捷径
第 3 次起   → 只能花钻石 60/120/240
复活之后一律重新保证有解             ← 广告换来的必须是能打通的局面
```

### 道具需要看广告

```
点道具 → 用下去没效果？        → 置灰，不弹任何东西
       → 还有免费次数？        → 直接用，不弹任何东西
       → 广告额度还有？        → 显示 📺，点了才播
       → 钻石够？              → 显示 💎 价格
       → 都没有                → 置灰
```

**先给甜头再收广告。** 前 5 关道具管够，把习惯养出来，之后在断供点收。
另有「道具箱」形态：一次广告开 3 个道具，单次价值更高、打断更少。

完整策略见 [`docs/03-广告与变现设计.md`](docs/03-广告与变现设计.md)。

## 代码结构

```
src/
├── core/                 游戏逻辑，纯 TS，不碰任何平台 API
│   ├── rng.ts            确定性随机（每日挑战同牌面 / 服务端复算反作弊）
│   ├── geometry.ts       牌堆几何 + 遮挡 DAG + 拓扑序
│   ├── solvable.ts       ★ 可解性保证，含证明
│   ├── deck.ts           组装成一副牌
│   ├── game.ts           状态机、道具、连击、复活
│   └── levels.ts         难度曲线
├── monetize/
│   ├── policy.ts         广告策略配置（全部数值集中在这里）
│   ├── ad-manager.ts     ★ 广告闸门：频控、兜底、埋点
│   ├── revive.ts         复活梯度
│   └── item-shop.ts      道具 → 广告 兑换流程
├── platform/
│   ├── adapter.ts        平台抽象接口
│   ├── douyin.ts         抖音实现（含预加载、超时兜底、防连点）
│   └── mock.ts           测试实现（可模拟无填充）
└── web/                  浏览器 Demo
```

## 本地运行

需要 Node ≥ 22.6（用了原生 TS type stripping，测试无需编译）。

```bash
npm install
npm run dev        # 浏览器 Demo → http://localhost:5173  （#level=50 可直达关卡）
npm test           # 36 个单测
npm run balance    # 关卡难度体检
npm run typecheck  # 严格模式类型检查
```

Demo 里有 **「模拟广告无填充」** 开关，用来验证兜底逻辑 ——
这条路径真机上很难复现，但线上一定会遇到。
