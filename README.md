# 羊群大整理 SheepSort

> 一个面向**抖音小游戏**的分栏整理游戏，以及一份《羊了个羊》爆火复盘。
> 一句话卖点：**不会让你白忙的分类游戏。**

本仓库包含两部分：

1. **研究** —— 《羊了个羊》为什么会爆，以及它为什么又迅速退潮（`docs/01`）
2. **实现** —— 可运行的游戏核心 + 求解器 + 广告与内购变现层，
   76 个单测，一个能玩的浏览器 Demo

## 玩法

1. 若干**栏位**，每栏能站 **4 只**羊。
2. 点一个栏位，拿起**栏口连续同品种的一群**羊。
3. 点另一个栏位放下。只能放进**空栏**或**栏口是同品种**的栏。
4. 一栏集满 4 只同品种 → **整栏出栏**，羊跑走，栏位空出来接着用。
5. 全部出栏 → 通关。**一步都走不动 → 失败。**

**空栏位是唯一的硬通货。** 所有难度、道具、广告位，本质上都围绕
「你还有几个空栏」这一件事。

> 为什么不做《羊了个羊》那种三消叠叠乐：一是玩法照搬只会被当成抄袭，
> 二是那个品类的红利窗口早就关了。分栏整理是长青品类，而且信息完全公开 ——
> 正好接上第一版真正想解决的问题。详见 [`docs/02` 第一节](docs/02-游戏设计-羊群大整理.md)。

## 核心承诺：每个局面都被真正解过

《羊了个羊》第二关的难，很大程度是**随机死局**的难 ——
玩家可能从第一步就已经必败，但要到卡槽爆掉才知道。
打了 50 次，第 51 次还是全靠运气，学不到任何东西。

本项目的做法：

> **每个关卡都由求解器实际解出一条通关路径，才发给玩家。**

我们手上不只有「有解」这个结论，还有一条**具体的解**（[`src/core/solver.ts`](src/core/solver.ts)）。
这条解顺带解决四件事：

| | 怎么用的 |
|---|---|
| **提示** | 从当前局面求解，给出下一步 |
| **牧羊犬** | 叼走一只羊可能让局面永远赢不了 → **只列出叼走后依然有解的栏位** |
| **重排** | 重新打散，**验证过有解**才交给玩家 |
| **复活** | 加了空栏位之后必须仍然有解，否则那 30 秒广告就是骗人的 |

还有一件《羊了个羊》做不到的：局面一旦变成无解，界面会**立刻告诉玩家**
（建议撤销或重排），而不是让他继续白点十几下才发现完了。

验证：80 关 × 4 种子 = 320 个局面，全部由求解器解出并**实际打通一遍**
（`test/solvable.test.ts`）。生成耗时 1~20ms。

### 效果：技巧真的决定胜负

`npm run balance` 用三档机器人跑通过率（每关每档 25 次）：

| 关卡 | 羊数 | 空栏 | random | greedy（普通玩家） | planner（老手） | 技巧收益 |
|---|---|---|---|---|---|---|
| 12 | 20 | 2 | 88% | 100% | 100% | +0pt |
| 24 | 24 | 2 | 88% | 88% | 100% | +12pt |
| 48 | 28 | 2 | 60% | 60% | 100% | +40pt |
| 52 | 28 | 1 | 24% | 32% | 92% | +60pt |
| 60 | 32 | 1 | 12% | 20% | 72% | +52pt |
| 66 ★ | 36 | 1 | 8% | 8% | 64% | +56pt |
| 76 | 36 | 1 | 8% | 12% | 72% | +60pt |

★ = 尖峰关（故意做的话题关，对应原作的「第二关」，但**可以被打过去**）

**最重要的一列是「技巧收益」（planner − greedy）**，后半段稳定在 +40~+60pt ——
决定胜负的是打法而不是运气。

> 这个结论来之不易。第一版的 planner 只做一步预判，跑出来和 greedy 几乎一样
> （技巧收益 ≈ 0），差点让我得出「这个玩法不吃技巧」的错误结论。
> 换成往下看 5 步的束搜索之后差距才显出来 —— **是测量工具不够强，不是玩法不够深。**

## 广告设计

三条原则，每一条都落成了代码里的配置项和断言：

1. **广告是玩家主动买的服务，不是我们强塞的税。**
   11 个广告位里 9 个是激励视频，插屏只有 1 个且有 240 秒冷却。
2. **永远不要因为广告没加载出来而惩罚玩家。**
   无填充照样发奖（标记 `fallback: true`，不计入广告收入）。
3. **前几分钟一分钱都不要赚。**
   冷启动 180 秒静默 + 前 5 关完全无广告。

### 失败后看广告继续

```
第 1 次复活 → 看广告 → +2 个空栏位
第 2 次复活 → 看广告 → +1 个空栏位     ← 递减，让广告是救援而不是捷径
第 3 次起   → 只能花钻石 60/120/240
每次复活后都跑一遍求解器；万一还是死的，自动重排成保证有解的局面
```

### 道具需要看广告

```
点道具 → 用下去没效果？   → 置灰，不弹任何东西
       → 还有免费次数？   → 直接用，不弹任何东西
       → 广告额度还有？   → 显示 📺，点了才播
       → 钻石够？         → 显示 💎 价格
       → 都没有           → 置灰
```

**先给甜头再收广告。** 前 5 关道具管够，把习惯养出来，之后在断供点收。
另有「道具箱」形态：一次广告开 3 个道具，单次价值更高、打断更少。

完整策略见 [`docs/03-广告与变现设计.md`](docs/03-广告与变现设计.md)。

## 充值设计

**广告卖次数，内购卖体验和身份** —— 两者绝不卖同一份价值，否则互相蚕食。
所以月卡和「去广告」都**只免插屏，不动激励视频**（付费用户依然自愿看广告换道具）。

充值弹窗的唯一原则：**在玩家已经用行为证明了需求之后才弹。**

| 商品 | 价格 | 触发时机 |
|---|---|---|
| 卡关救援包 | 12 元 | 同一关连输 3 次 |
| 钻石包 | 6 / 30 / 98 / 328 元 | 钻石不够导致操作失败的那一刻 |
| 首充礼包 | 6 元 | **第一次靠广告复活成功之后** |
| 月卡 | 30 元 | 累计看 15 支广告 或 连登 3 天 |
| 去广告 | 18 元 | 被插屏打断 3 次以上 |

首充那一条最值得琢磨：不是进游戏就弹，而是玩家刚刚亲手付出 30 秒换到复活之后 ——
价值锚点是他刚付出的那 30 秒，而不是空气。

另外每个弹窗都有「关掉 N 次就永久不再弹」。这不是让钱：
反复糊脸的弹窗会让玩家练出「见到就关」的肌肉记忆，之后再也转化不了。

⚠️ **iOS 上历来无法虚拟支付**，所以广告是所有人的收入地板，内购只是 Android 上的上限。
代码里把「这台设备不能充值」当成一等状态，此时所有充值入口连按钮都不画。

完整触发表、定价理由和红线见 [`docs/05-盈利模型.md`](docs/05-盈利模型.md)。

## 代码结构

```
src/
├── core/                 游戏逻辑，纯 TS，不碰任何平台 API
│   ├── rng.ts            确定性随机（每日挑战同局面 / 服务端复算反作弊）
│   ├── board.ts          规则层：合法移动、出栏、状态指纹
│   ├── solver.ts         ★ 求解器（DFS + 规范化去重 + 启发式排序）
│   ├── generator.ts      关卡生成：铺牌 → 求解验证 → 不过就重抽
│   ├── game.ts           状态机、道具、连击、评星、复活
│   └── levels.ts         难度曲线
├── monetize/
│   ├── policy.ts         广告策略配置（全部数值集中在这里）
│   ├── ad-manager.ts     ★ 广告闸门：频控、兜底、埋点、权益免插屏
│   ├── revive.ts         复活梯度
│   ├── item-shop.ts      道具 → 广告 兑换流程
│   ├── iap.ts            内购商品表与权益（含 iOS 不可支付这条约束）
│   └── offers.ts         ★ 充值触发引擎：什么时候弹、弹哪个
├── platform/
│   ├── adapter.ts        平台抽象接口
│   ├── douyin.ts         抖音实现（含预加载、超时兜底、防连点）
│   └── mock.ts           测试实现（可模拟无填充）
├── web/                  浏览器 Demo（黏土 3D 质感，纯 CSS，支持深色模式）
└── tools/
    ├── bots.ts           三档模拟玩家（含束搜索）
    └── balance.ts        关卡难度体检
```

## 本地运行

需要 Node ≥ 22.6（用了原生 TS type stripping，测试无需编译）。

```bash
npm install
npm run dev        # 浏览器 Demo → http://localhost:5173  （#level=60 可直达关卡）
npm test           # 76 个单测
npm run balance    # 关卡难度体检
npm run typecheck  # 严格模式类型检查
```

Demo 里有 **「模拟广告无填充」** 开关，用来验证兜底逻辑 ——
这条路径真机上很难复现，但线上一定会遇到。
