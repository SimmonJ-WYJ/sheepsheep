# 上线与资质清单

> ⚠️ **免责声明：这份清单是工程视角的整理，不是法律意见。**
> 国内游戏资质政策（尤其版号）变动频繁，每一条都**必须**去下面列的官方渠道
> 核实当期口径。周期是经验区间，不是承诺。

## 一、为什么资质排在代码前面

代码写多快都没用 —— **版号决定你什么时候能开内购**，而版号的周期以月计。
所以正确的做法是：**资质流程和开发并行启动**，别等做完了才去办。

一句话判断你处在哪条路上：

```
想做内购（充值）？
├── 是 → 必须有版号 → 版号要通过有出版资质的发行商申报 → 周期以月计
└── 否 → 只做广告变现 → 门槛低得多，但当期政策要核实
```

## 二、需要办的东西，按顺序

### 1. 企业主体（营业执照）

小游戏做变现基本要企业账号，个人开发者做不了商业化。

- 如果还没有：注册一个公司，常见 1~2 周
- 已有就跳过

### 2. 抖音开放平台开发者账号 + 小游戏

- 入口：[抖音开放平台](https://developer.open-douyin.com/)
- 用企业主体注册、完成企业认证
- 创建「小游戏」类型的应用，拿到 **appid**（填进 `douyin/project.config.json`）
- 周期：数天 ~ 2 周（看认证审核）

### 3. 软件著作权登记（软著）

**这是申请版号的前置条件，也是小游戏过审通常要求的材料。现在就该开始办。**

办理机构：中国版权保护中心（现基本全程网办）。

**要交的材料**

| 材料 | 说明 |
|---|---|
| 申请表 | 线上系统填写 |
| **源代码文档** | 前 30 页 + 后 30 页；不足 60 页则全部提交 |
| **软件说明书** | 带截图的操作说明，通常 20~30 页 |
| 主体证明 | 企业交营业执照副本；个人交身份证 |

**填表要素**

- 软件名称：建议 `XXX小游戏软件`，不要用纯英文、不要含「中国」「国家」等词
- 版本号：`V1.0`
- 开发完成日期 / 首次发表日期
- 权利取得方式：原始取得
- 权利范围：全部权利

**源代码文档的格式硬要求（退回率最高的地方）**

- **每页不少于 50 行** ← 最常见的退回原因
- 页眉：软件全称 + 版本号；页脚：页码
- 不能出现其他单位/个人的著作权信息

**周期与费用**

- 普通：约 30~60 个工作日
- 加急：分 3 / 5 / 10 / 15 个工作日几档，**加急要额外付费**
- 自己办 vs 找代理：自己办省钱但要自己处理格式补正；代理通常几百到两千元

> 具体材料清单和格式以中国版权保护中心当期的《填表说明》为准。

### 本项目的源代码文档已经能一键生成

```bash
npm run copyright
```

产出 `copyright/源代码.txt`：按 50 行/页切页、加好页眉页脚、取前 30 页 + 后 30 页
（本项目 3918 有效行 = 79 页），并自动做两项自查：

1. **第三方著作权信息**（`Copyright` / `©` / `Licensed under`）
2. **竞品名称与评价性措辞** —— 会在**提交文件里**替换掉，
   但**不动仓库源码**。仓库里写明「某个设计在回避什么」对维护者有价值；
   软著申请文件里反复点名其他公司产品还带评价，既有风险也不专业。
   平台名（抖音 / 微信 / 苹果）不在净化范围内 —— 接入某平台的代码出现该平台名称完全正常。

`copyright/软件说明书.md` 是说明书草稿，标了 `【截图】` 的位置补上截图、
贴进 Word 设好页眉页脚导 PDF 就能交。

### 4. 版号（网络游戏审批文号）

**有内购就必须有。这是整条链路上最长的一环。**

- 审批机关：国家新闻出版署（NPPA）
- 关键点：**个人和一般公司不能自己提交**，必须通过有**出版资质**的单位（发行商）申报
- 周期：**数月起**，且不确定。没有任何人能给你承诺时间
- 现实做法：找发行商代理，他们出版号和买量，你分成（常见 3:7 ~ 5:5）

### 5. 变现能力开通

- 在抖音开放平台申请**流量主 / 广告变现**能力
- 逐个申请广告位，拿到 adUnitId，填进 `src/monetize/policy.ts` 的 `PLACEHOLDER_AD_UNITS`
- 激励视频 / 插屏 / Banner 是分开申请的

### 6. 虚拟支付开通（要版号）

- 拿到版号之后才能开通
- iOS 侧的虚拟支付另有限制，见 [`docs/05` 第零节](./05-盈利模型.md)
- 代码侧已经准备好：`paymentAvailability()` 运行时探测 + `iosPaymentEnabled` 远端开关

### 7. 合规必备件

- **防沉迷 / 实名认证**：接入平台提供的能力，未成年人时段和消费限制
- **隐私政策 + 用户协议**：需要有可访问的页面
- **内容审核**：素材、文案、话题标签都会过审

## 三、两条上线路径

### 路径 A：先上纯广告版（推荐用来验证玩法）

```
企业主体 → 开放平台账号 → 提交小游戏审核 → 开通广告变现 → 上线跑数据
                              ↓（并行）
                        办软著 → 找发行商 → 申版号 → 再开内购
```

好处：**几周内就能拿到真实的留存和 ARPDAU 数据**，而不是等几个月。
数据好看再去谈发行，谈判位置完全不同。

代码侧要做的：把内购入口整体关掉（下面第四节讲怎么关）。

⚠️ **"纯广告变现要不要版号"这条口径一直在变，务必先去开放平台确认。**

### 路径 B：直接找发行商

你出玩法和数据，发行商出版号 + 买量。

现在这个仓库正好就是谈发行的材料：
- 可玩 demo（`npm run dev`）
- **实测通过率曲线**（`npm run balance`）—— 这个东西大部分独立开发者拿不出来
- 完整的变现设计文档（`docs/03` `docs/05`）
- 85 个单测证明工程质量

## 四、没有版号时怎么关掉内购

代码里不需要删任何东西，**内购入口本来就是能整体关掉的**：

```ts
// 版号还没下来时，直接告诉引擎「这台设备不能充值」
const offers = new OfferEngine({ availability: 'unavailable' }, bootAt);
// offers.canPay === false → 所有充值弹窗和按钮一个都不出
```

关掉之后玩家仍然完全能玩：钻石靠 `economy.ts` 的免费通路获取
（签到 / 侧边栏 / 评星 / 每日挑战 / 看广告换钻，每日 275 钻），
足够撑起每天 1~2 次钻石复活 —— 这条路径有单测覆盖。

**所以纯广告版不是阉割版，是一个完整的游戏。**

## 五、上线前的技术检查清单

**打包**
- [ ] `douyin/project.config.json` 填了真实 appid
- [ ] `PLACEHOLDER_AD_UNITS` 换成真实广告位 id
- [ ] 首包体积达标（抖音有限制，超了要分包）
- [ ] 真机跑过 iOS + Android 各一台

**广告（真机验，模拟器不算）**
- [ ] 激励视频：看完 / 中途退出 / 无填充 三条分支
- [ ] 广告超时兜底（飞行模式模拟）
- [ ] 冷启动 180 秒静默、前 5 关无广告
- [ ] 跨天额度重置（改系统时间）

**内购（有版号才测）**
- [ ] 支付成功 / 取消 / 失败三条分支
- [ ] **服务端收据校验**（没有这个一定被刷）
- [ ] 权益到期（月卡）
- [ ] iOS 上支付入口确实不出现

**合规**
- [ ] 激励视频播放前有明确奖励告知
- [ ] 无诱导分享文案
- [ ] 防沉迷接入
- [ ] 隐私政策 / 用户协议可访问

**性能**
- [ ] 低端机帧率
- [ ] 求解器耗时不卡首帧（第 80 关生成约 20ms）
- [ ] `onHide` 暂停计时器和音频
