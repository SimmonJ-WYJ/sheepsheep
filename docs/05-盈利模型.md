# 盈利模型：什么时候看广告，什么时候让他充值

> 对应代码：`src/monetize/iap.ts`（商品与权益）、`src/monetize/offers.ts`（触发引擎）
> 广告侧的细节在 [`docs/03`](./03-广告与变现设计.md)，这一篇讲**时机**和**两者怎么分工**。

## 零、先说一条会决定整个模型结构的约束

国内小游戏平台（微信 / 抖音）在 **iOS 上历来无法做虚拟支付** ——
苹果不允许绕过 App Store 的内购分成。具体政策会变，
**上线前必须按当期规范核实**，但架构上必须把
「这台设备根本不能充值」当成一等状态，而不是一个报错。

推论：

- **广告是所有人的收入地板**，iOS 用户基本只能靠广告
- **内购是 Android 上的上限**，不能作为收入的必要条件
- 任何「不充值就玩不下去」的设计，在 iOS 上等于直接劝退一半用户

代码里这条约束是 `PaymentAvailability`。设备不能充值时
`OfferEngine.canPay` 为 false，**所有充值入口连按钮都不画**：

```ts
if (!this.canPay) return { show: false, reason: 'payment-unavailable' };
```

## 一、广告和内购必须卖不同的东西

最常见的错误是让两者卖同一份价值：既能看广告拿加栏，又卖加栏钻石包。
结果玩家算一笔账 —— 看 30 秒能拿到的东西，凭什么花钱买？
于是内购转化不起来，广告收入也没涨。

正确的分工：

| | 卖什么 | 例子 |
|---|---|---|
| **广告** | 一次性的小额救急 | 单次复活、单次道具 |
| **内购** | 省时间 / 免打扰 / 身份 | 钻石包、月卡、去插屏、皮肤 |

一句话：**广告卖次数，内购卖体验和身份。**

这也解释了一条容易做错的细节：**月卡和「去广告」只免插屏，绝不去掉激励视频入口。**
激励视频是玩家自愿点开、能换到东西的；顺手一起去掉等于白白断掉
付费用户继续贡献广告收入的路，而且玩家根本没要求去掉它。

`AdManager` 里这条是强制的（有单测守着）：

```ts
// 买了月卡 / 去广告的玩家，插屏和 banner 一律不出。激励视频不在此列。
if (rule.format !== 'rewarded' && this.isInterstitialFree()) {
  return { allowed: false, reason: 'entitled' };
}
```

## 二、什么时候看广告：一次会话的时间线

```
0:00  ┌ 冷启动。前 180 秒一个广告都没有。
      │
0:30  │ 第 1~5 关：完全无广告，道具管够。
      │   目的只有一个 —— 让第一印象是「这游戏挺好玩」而不是「广告真多」。
      │
3:00  ├ 静默期结束。第 6 关起，关卡之间的自然断点可能出现**插屏**
      │   （240 秒冷却，每日上限 5 次，是唯一的强制广告）。
      │
      │ 局内：道具免费次数用完 → 按钮变成 📺 → 玩家点了才播。
      │   ⚠️ 道具用下去没效果时按钮置灰，绝不放行到广告。
      │
      ├ 失败 → 复活弹窗。第 1 次广告换 2 个空栏位，第 2 次换 1 个。
      │   这是**主力广告位**，豁免全局间隔（玩家刚输，意愿最高）。
      │
      ├ 结算页 → banner。
      │
      └ 牧场离线收益 / 每日签到 → 「看广告翻倍」。
          接受度最高的形态，几乎无损体验。
```

硬性天花板：**激励视频每日 20 次，插屏每日 5 次。**
这不是保守 —— 超过这个量级的用户基本处在「被广告淹没」的状态，第二天不会回来。

## 三、什么时候让他充值

### 唯一的核心原则

> **在玩家已经用行为证明了需求之后才弹，绝不提前弹。**

反例（也是绝大多数小游戏的做法）：一进游戏就弹首充。
这时玩家对游戏还没有任何感情，弹窗只传达一件事：「这游戏想掏我钱」。
转化率极低，而且污染第一印象，连带压低次留。

所以下面每一条触发条件，都是一个**玩家已经表达了需求**的信号。

### 触发表

这张表就是「什么时候」的全部答案，代码里是 `offers.ts` 的 `RULES`：

| 商品 | 价格 | 触发时机 | 为什么是这个时机 |
|---|---|---|---|
| **卡关救援包** | 12 元 | 同一关**连输 3 次** | 需求最明确的时刻，转化率最高的场景 |
| **钻石包** | 6 / 30 / 98 / 328 元 | **钻石不够导致操作失败**的那一刻 | 玩家自己撞到了墙，不是我们推的 |
| **首充礼包** | 6 元 | **第一次靠广告复活成功之后** | 见下方详述 |
| **月卡** | 30 元 | 累计看 **15 支广告** 或 **连登 3 天** | 已在大量支付时间成本，可升级为金钱成本 |
| **去广告** | 18 元 | 被插屏打断 **3 次以上** | 给厌广用户一个花钱的出口，否则他们只会卸载 |

优先级从上到下递减。同时满足多个条件时只弹最上面那个；
如果它被频控挡住，会**退到次优的那个**而不是什么都不弹（有单测）。

### 首充礼包的时机最值得琢磨

不是「进游戏」，不是「第一次失败」，而是 **第一次靠广告复活成功之后**。

玩家刚刚亲手付出 30 秒换到了继续游戏的机会 ——
他已经用行动证明了「这一关值得我付出成本」。
此时 6 元礼包的价值锚点是**他刚刚付出的那 30 秒**，而不是空气。

```ts
when: (s) => s.adRevivesThisSession >= 1,
rationale: '第一次广告复活之后：玩家刚用 30 秒证明了付费意愿',
```

### 第二条原则：关掉几次就永久别再弹

每个弹窗都有 `maxShows` 和 `maxDismiss`。玩家主动关掉 N 次之后就再也不弹。

这条经常被当成「让钱」，其实反了：

- 一个从不骚扰人的弹窗，玩家在真正需要的时候才会点开看
- 一个反复糊脸的弹窗，玩家会训练出「见到就关」的肌肉记忆，之后再也转化不了

### 新手保护

充值弹窗的静默期比广告更长：**冷启动 5 分钟 + 前 8 关**，一个都不出。

## 四、定价说明

| 决策 | 理由 |
|---|---|
| 首充 6 元 | 国内小游戏的首充锚点，几乎所有休闲游戏都用它 |
| 首档钻石包 300 钻 | **必须刚好买得起 2~3 次复活**。如果首档买不起一次复活，玩家会觉得「这钱花了没用」（有单测强制这条） |
| 月卡 30 元 | 每天 1 元，最容易被接受的心理账户 |
| 大额档位单价递减 | 10% → 20% → 28% 赠送，有单测强制「越大越便宜」 |

价格用**分**存储（`priceFen`）而不是元，避免浮点误差。
所有数值都应该走远端配置下发，`SKUS` 只是冷启动兜底。

## 五、绝对不要做的

- ❌ **开屏就弹充值。** 见上文。
- ❌ **体力 / 心系统。** 抖音是即点即玩的场景，体力墙会直接把人赶走。
- ❌ **卖关卡解锁。** 那是买断制思路，在休闲游戏里会直接砍断留存漏斗。
- ❌ **卖「保证有解」。** 这是本作的核心价值主张（见 `docs/02`）。
  一旦它变成付费功能，等于承认免费玩家玩的是死局版本 ——
  整个产品的立足点就崩了。**这条是产品底线，不是数值问题。**
- ❌ **付费影响排行榜公平性。** 每日挑战是全服同一局面，
  用了付费道具的成绩要么单独成榜，要么标注出来。
- ❌ **诱导分享。** 抖音和微信都明令禁止。分享要做成「可选的额外奖励」。

## 六、怎么算钱

```
LTV = 广告 LTV + 内购 LTV

广告 ARPDAU = 人均激励视频次数 × 激励 eCPM / 1000
            + 人均插屏次数     × 插屏 eCPM / 1000
            + 人均 banner 曝光 × banner eCPM / 1000

内购 ARPDAU = 付费率 × ARPPU / 计费周期
```

休闲小游戏的常见量级（**必须用自己的数据校准，别直接用**）：

| 指标 | 常见区间 |
|---|---|
| 付费率 | 1% ~ 3% |
| ARPPU | 20 ~ 50 元 |
| 人均激励视频 | 3 ~ 8 次/DAU |

注意 iOS 的内购那一项要按 0 算。如果你的用户里 iOS 占比高，
整体模型会更偏向广告 —— 这会直接影响你该把精力放在哪。

## 七、上线后怎么调

1. **整张 `RULES` 表走远端配置下发**，不要硬编码进包体。
2. **分层 AB，一次只动一个旋钮。** 优先测：
   - 首充触发点（广告复活 1 次 / 2 次 / 关卡通过 10 关）
   - 月卡触发阈值（10 / 15 / 25 支广告）
   - `maxDismiss`（1 / 2 / 4）—— 这个值对长期转化的影响常被低估
3. **看 7 日累计 LTV，不是当日 ARPDAU。**
   几乎所有加广告加弹窗的改动都能抬高当日 ARPDAU，
   只有一部分能抬高 7 日 LTV，剩下的都是在借明天的钱。
4. **必看的护栏指标**：
   - 次留、第 2~8 关流失率
   - 单用户日均广告次数分布的 **P90**（异常说明有一小撮人被反复轰炸）
   - 充值弹窗的 **关闭率**（超过 80% 说明时机选错了，不是文案问题）

## 八、埋点

`OfferEngine.decide()` 返回的 `offer.rationale` 就是给埋点用的 ——
每次展示都记下**是哪条信号触发的**，才能回答
「到底哪个触发点在赚钱」这个问题。

`OfferDecision` 的 `reason` 也要上报：

- `payment-unavailable` → iOS 占比
- `nothing-triggered` → 触发条件是不是定得太严
- `all-gated` → 频控是不是卡太死
