# 抖音小游戏接入

> 对应代码：`src/platform/`
> **重要：`tt.*` 的 API 会随基础库版本变化。接入前请对照当天的**
> **[官方文档](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/develop/api/)**
> **核对本文提到的每一个方法。** 本文写于开发期，仅作为接入路线图。

## 一、为什么选抖音小游戏

| 能力 | 抖音 | 微信小游戏 |
|---|---|---|
| 流量分发 | 信息流 + 搜索 + **视频挂载** | 主要靠社交裂变 |
| 侧边栏复访 | ✅ 有，且有专门的复访奖励机制 | ❌ |
| 录屏 → 一键发布短视频 | ✅ 原生支持 | ❌ |
| 内容生态联动 | 达人可直接挂载小游戏 | 弱 |

对本作最关键的是**录屏发布**：
「通关瞬间自动剪成短视频 + 话题标签一键发布」是成本最低的自然量入口，
也正好接上《羊了个羊》靠二创视频起量的路径 —— 只不过这次是内置的。

## 二、架构分层

```
src/
├── core/        游戏逻辑，纯 TS，不碰任何平台 API
├── monetize/    变现逻辑，只依赖 platform/adapter.ts 接口
├── platform/
│   ├── adapter.ts   平台抽象接口
│   ├── douyin.ts    抖音实现（tt.*）
│   └── mock.ts      测试/本地调试实现
└── web/         浏览器 Demo（Vite）
```

**游戏逻辑和变现逻辑绝不直接引用 `tt`。**

好处：
- 在 Node 里跑单测（`MockPlatform` 能模拟无填充、中途退出等真机难复现的分支）
- 在浏览器里调 UI
- 以后要上微信 / 快手小游戏，只加一个 adapter 文件

## 三、渲染层选型

本仓库的 `src/web` 是 DOM + 纯 CSS（黏土 3D 质感）实现的**玩法验证 Demo**，
不是最终美术，但配色、动效和交互节奏可以直接作为美术需求的参考。

正式包建议 **Cocos Creator 3.x**：
- 对抖音小游戏的适配最成熟，有官方发布模板
- 处理好了触摸、适配、音频、资源加载这些坑
- `src/core` 和 `src/monetize` 可以**原样搬过去**（纯 TS，无 DOM 依赖）

迁移时只需要：
1. 把 `src/core` `src/monetize` `src/platform` 复制进 Cocos 项目的 `assets/scripts`
2. 写一套 Cocos 的渲染层，消费 `SortGame` 的状态
3. `DouyinPlatform` 直接可用

## 四、用到的 `tt` API

### 激励视频（核心）

```ts
const ad = tt.createRewardedVideoAd({ adUnitId });
ad.load();                                  // 提前预加载
ad.onClose(res => { res.isEnded /* 看完 */ });
ad.onError(err => { /* 无填充/报错 */ });
ad.show();
```

`src/platform/douyin.ts` 在这之上加了三层保护：

1. **预加载** —— 构造时就 `load()`，播完立刻预热下一支
2. **超时兜底** —— 12 秒没有任何回调就当失败处理，
   避免 Promise 永远悬着把游戏卡死
3. **防连点** —— 上一支还在播就直接拒绝，不叠两层广告

```ts
const timer = setTimeout(() => finish({ kind: 'error', message: 'timeout' }),
                         REWARDED_TIMEOUT_MS);
```

> 超时这一条是实践里最容易漏的。真机上偶发「点了没反应也不报错」，
> 没有超时兜底就是一个必现的卡死。

### 插屏 / Banner

```ts
tt.createInterstitialAd({ adUnitId });
tt.createBannerAd({ adUnitId, style: { left, top, width } });
```

Banner 用 `getSystemInfoSync()` 算居中位置，宽度封顶 375。

### 侧边栏（抖音特有，重点）

```ts
tt.checkScene({ scene: 'sidebar', success: res => res.isExist });
tt.navigateToScene({ scene: 'sidebar' });
tt.getLaunchOptionsSync().scene;   // 判断是不是从侧边栏进来的
```

**这是一个不花广告成本的高价值召回位。**
建议做法：引导玩家从侧边栏进入一次，之后每天从侧边栏进入送一份道具礼包。
成本为零，对次留的拉动通常比多播两条广告大得多。

### 录屏 + 发布

```ts
const rec = tt.getGameRecorderManager();
rec.start({ duration: 60 });
rec.onStop(res => res.videoPath);
rec.stop();

tt.shareAppMessage({
  channel: 'video',
  extra: { videoPath, hashtag_list: ['羊群大整理'], videoTopType: 1 },
});
```

触发时机建议：
- 通关**尖峰关**的瞬间（最有炫耀价值）
- 打出高连击时
- 每日挑战拿到高排名时

不要每关都弹，会烦。

### 存档

```ts
tt.getStorageSync(key) / tt.setStorageSync(key, value)
```

`AdManager` 的当日额度就存在这里，杀进程重进不会绕过上限。
`douyin.ts` 里 storage 的读写都包了 try/catch —— 存档失败不该影响游戏进行。

## 五、排行榜

抖音小游戏**没有**微信那样的开放数据域，需要自建服务：

```
客户端 → tt.login() 拿 code
       → 自己的服务端换 openid
       → 上报分数 / 拉取榜单
```

**反作弊**：牌面完全由 seed 决定，服务端可以用同一个 seed 复算牌局，
校验客户端上报的分数是否可能达成。这是选择确定性 RNG 的一个额外收益
（见 `src/core/rng.ts`）。

榜单建议：
- 每日挑战榜（全国 / 城市 / 好友）
- 城市榜 —— 对应《羊了个羊》的省份榜，把个人失败接入集体身份

## 六、上线检查清单

**接入前**
- [ ] 在抖音开放平台创建小游戏，拿到 appid
- [ ] 申请激励视频 / 插屏 / Banner 广告位，把 id 填进 `PLACEHOLDER_AD_UNITS`
- [ ] 配置服务端域名白名单（排行榜接口）

**功能**
- [ ] 激励视频：看完 / 中途退出 / 无填充 三条分支都在真机验过
- [ ] 广告超时兜底真机验过（可以用飞行模式模拟）
- [ ] 冷启动静默期、新手关免广告生效
- [ ] 跨天额度重置（改系统时间验一次）
- [ ] 侧边栏引导 + 复访奖励
- [ ] 录屏发布链路

**合规**
- [ ] 激励视频播放前有明确的奖励告知
- [ ] 无诱导分享文案
- [ ] 防沉迷接入
- [ ] 隐私政策 / 用户协议
- [ ] 逐条对当期审核规范

**性能**
- [ ] 首包体积（抖音有限制，超了要用分包）
- [ ] 低端机帧率与求解器耗时（第 80 关 36 只羊，生成约 20ms，注意别卡首帧）
- [ ] `onHide` 时暂停计时器和音频

## 七、本地开发

```bash
npm install
npm run dev        # 浏览器 Demo，http://localhost:5173
                   # 支持 #level=50 直达指定关卡
npm test           # 53 个单测，含求解器验证和广告频控
npm run balance    # 关卡难度体检
npm run typecheck  # 严格模式类型检查
```

Demo 里有一个 **「模拟广告无填充」** 开关，
勾上之后所有激励视频都会返回 error，用来验证兜底逻辑 ——
这条路径在真机上很难稳定复现，但线上一定会遇到。
