# 《叠羊记》游戏设计文档

> 代号 SheepStack。定位：抖音小游戏，三消叠叠乐，
> 一句话卖点 —— **「不坑人的羊了个羊」**。

## 一、定位与差异化

| | 羊了个羊 | 叠羊记 |
|---|---|---|
| 牌面生成 | 随机铺，可能死局 | **保证有解**，先造解法再铺牌 |
| 难度来源 | 运气 | 卡槽压力 + 规划深度 |
| 洗牌道具 | 纯随机，可能越洗越死 | **重新保证有解** |
| 关卡 | 2 关 | 200+ 关主线 + 每日 + 无尽 + 对战 |
| 长期目标 | 无 | 牧场养成 + 羊图鉴 |
| 复活 | 看广告 / 分享 | 递减梯度 + **复活后重新保证有解** |
| 信息 | 下层完全看不见 | 透视道具 + 顶层半透明提示 |

一句话概括差异：**把「拼运气」改成「拼规划」。**

## 二、核心玩法

和经典三消叠叠乐一致，不做加法：

1. 牌堆分层叠放，上层遮住下层，只有**完全没被压住**的牌可以点。
2. 点一张牌 → 进入底部**卡槽（7 格）**。
3. 卡槽内凑齐 **3 张相同图标** → 自动消除，释放 3 格。
4. 清空所有牌 → 通关。
5. **卡槽放满 7 格且没有发生消除 → 失败。**

底部另有「牌河」：若干条竖直堆叠的牌垛，只有最上面一张可点，
用来制造「明牌但拿不到」的规划压力。

## 三、核心创新：可解性保证

这是整个项目的技术地基，实现在 `src/core/solvable.ts`。

### 问题

随机铺牌 → 玩家可能从第一步就已经必败。这是《羊了个羊》最大的设计债。

### 做法：反向生成

```
1. 先生成牌堆几何结构（位置 + 遮挡关系）→ 得到一个有向无环图
2. 对这个 DAG 取一条拓扑序 order
   —— order 的含义是：按这个顺序取牌，每张牌被取时都恰好是可点的
3. 沿着 order 逐张分配「组」（每组 3 张），同时模拟卡槽占用，
   每一步只从「不会让卡槽溢出」的动作里选
4. 走完 order，卡槽全程没有超限 → order 本身就是一条通关路径
```

三种分配动作：

- `complete` —— 给已有 2 张的组补第 3 张，立即消除，卡槽 −2
- `grow` —— 给已有 1 张的组补第 2 张，卡槽 +1
- `new` —— 开一个新组，卡槽 +1

**永远不会走进死路**，由两条不变量保证（严格证明写在
`src/core/solvable.ts` 的注释里，这里只说结论）：

- (A) 同时开着的组数 `D ≤ usable − 1`，其中 `usable = 卡槽格数 − 1`
- (B) `needed ≤ remaining`（还差几张才能收口 ≤ 还剩几张牌）

> `usable = capacity − 1` 是因为**放满 7 格且没消除就算输**，
> 所以只有 `complete` 能瞬时摸到第 7 格。这个细节最初写错过一次，
> 被单测在第 20 关抓了出来。

### 组 vs 图标

生成时用「组」证明可解性，但玩家看到的是「图标」，多个组可以复用同一个图标。

这样做安全，而且是我们想要的：消除按图标判定，如果两个组共用「青草」，
凑齐任意 3 张青草就会消除 —— 这只会**比模拟时更早**释放卡槽，
占用永远 ≤ 模拟值，通关路径依然成立。

更进一步，可以证明**走完全部牌之后卡槽一定是空的**：
每组恰好 3 张，一个图标是若干个组的并集，所以每种图标的总数必然是 3 的倍数
（这条性质有单测守着）。

### 洗牌 = 重新保证有解

玩家自己走进死路是允许的 —— 那是技巧的一部分。
但我们提供一条出路：**洗牌道具会把当前卡槽内容当作起始手牌，
对剩余牌堆重跑一遍反向生成**，因此洗牌之后一定还能通关。

这和《羊了个羊》的洗牌（纯随机、可能越洗越死）是本质区别。

### 每日挑战：同一副牌

牌面完全由 seed 决定（`src/core/rng.ts` 用 mulberry32，不用 `Math.random`）。
`seed = 日期` 就能让全球玩家拿到同一副牌，不需要下发牌面数据；
服务端也可以用同一个 seed 复算牌局来校验分数，反作弊。

## 四、道具体系

| 道具 | 效果 | 设计意图 |
|---|---|---|
| ↩ 撤销 | 退回上一步（含被消掉的三张） | 容错，降低挫败 |
| ⬆ 移出 | 卡槽最前 3 张退回牌堆 | 救急，最直接的解围手段 |
| 🔀 洗牌 | 重排剩余牌堆，**重新保证有解** | 从死路里救回来，本作特色 |
| 👁 透视 | 点亮 6 张被压住的牌 | 把「赌」变成「算」，本作特色 |
| ➕ 卡槽 | 本关卡槽 +1 格 | 高价值道具，直接降低难度 |

**关键规则：道具用下去没效果时一律置灰，绝不放行到广告。**
比如卡槽是空的还点「移出」—— 让玩家看完 30 秒广告换来一个点下去什么都没发生的
道具，是最直接的差评来源。这条由 `game.canUseItem()` 强制，有单测守着。

前 5 关道具管够，之后收紧、由广告补给。先把使用习惯养出来，
再在断供点收广告，长期总收入更高（详见 `docs/03`）。

## 五、关卡与难度曲线

`src/core/levels.ts` 程序化生成，主要旋钮：

| 旋钮 | 作用 |
|---|---|
| `maxOpenGroups` | **真正的难度旋钮**。越接近上限（=5），越要求提前规划 |
| `iconCount` | 图标种类。越多越难凑，封顶 9 |
| `layers` / `gridBase` | 牌数和层数，影响视觉复杂度和信息缺失程度 |
| `weightNewGroup` | 解法路径里「开新组」的倾向，越高卡槽越吃紧 |
| `timeLimitSec` | 第 26 关起进场 |

### 实测通过率

`npm run balance` 会用三档机器人模拟真人跑通过率
（random = 乱点，greedy = 只看手上快满的图标，planner = 会避开把同图标闷死的点法）。

摘录（每关每档 40 次）：

```
  关卡   牌数  层数  图标  同开组  限时   random greedy planner
     1      12     2     3      2     -   100%  100%  100%
    12      27     3     4      2     -    60%   98%  100%
    25      45     4     5      3     -     3%   85%   95%
    35 *    69     5     7      4   275     0%   38%   68%
    45      57     5     6      3   247     0%   60%   85%
    50 *    90     6     8      4   233     0%    5%   33%
    55      69     5     7      4   219     0%   20%   80%
    60      75     6     7      4   206     0%   30%   65%
                                            * = 尖峰关
```

**这张表里最重要的一列是 greedy 和 planner 的差距。**
第 55 关 greedy 只有 20%、planner 有 80% —— 说明决定胜负的是打法而不是运气。
这正是《羊了个羊》做不到的：在那里，两档机器人的差距很小。

如果哪一关 planner 也低于 40%，说明是牌面本身太挤而不是玩家菜，
`tools/balance.ts` 会把它单独标出来要求复看。

### 尖峰关

第 10 / 20 / 35 / 50 / 66 / 88 关难度陡增，是**故意**留的话题位 ——
对应《羊了个羊》的「第二关」，用来制造「我卡在 50 关三天了」这类短视频素材。
区别在于：它们**可以被打过去**，只是需要认真规划或者用道具。

## 六、模式

| 模式 | 说明 | 作用 |
|---|---|---|
| 主线闯关 | 200+ 关，程序化生成 + 手调尖峰关 | 主留存 |
| 每日挑战 | 全服同一副牌，限时，排行榜 | 每日回访 |
| 无尽模式 | 牌堆不断补充，比谁撑得久 | 高手向，排行榜内容 |
| 好友对战 | 异步 PVP：同一副牌，比时间/分数 | 社交传播 |

## 七、留存承接：牧场系统

《羊了个羊》没有的部分，也是长线的关键。

- 通关获得**草料**，草料养羊
- 每只羊有**被动技能**（如「开局多 1 格卡槽」「每关首个道具免费」）
- 羊有**图鉴**和稀有度，收集驱动
- 牧场产生**离线收益**，看广告可翻倍（一个高接受度的广告位）

作用：给「今天为什么要打开这个游戏」一个玩法之外的答案。

## 八、社交与传播

1. **复活分享** —— 动机最强的时刻放传播动作（沿用羊了个羊）
2. **城市榜 / 好友榜** —— 把个人失败接入集体身份（沿用省份榜思路）
3. **抖音录屏一键发布** —— 通关瞬间自动剪辑成短视频，
   带话题标签直接发布。这是抖音小游戏相对微信的独有优势，
   也是成本最低的自然量入口（见 `docs/04`）
4. **尖峰关话题** —— 官方在抖音发起「#XX关有人过了吗」挑战

## 九、特殊牌（Roadmap，当前未开启）

| 牌 | 效果 | 状态 |
|---|---|---|
| ⭐ 万能牌 | 可顶替任意图标 | **已实现但默认关闭**（`wildCount: 0`） |
| ❄ 冰冻牌 | 需要消两次 | 未实现 |
| 💣 炸弹牌 | 限时未消除则判负 | 未实现 |
| 🧲 磁铁牌 | 自动吸附同图标 | 未实现 |

**万能牌为什么默认关掉：** 它会破坏可解性证明。
如果万能牌被贪心地用去补 A 图标，可能导致 B 图标最后剩 2 张卡死。
当前实现的安全版本是「万能牌保留原始图标，默认按原图标参与消除，
玩家可以显式改写它」—— 这样生成期的通关路径始终成立。
在把「供给感知的万能牌消耗策略」和对应的单测做出来之前，不要在正式关卡里打开。

冰冻牌同理（「消两次」会打破每种图标总数是 3 的倍数这条性质），需要重新推导。
